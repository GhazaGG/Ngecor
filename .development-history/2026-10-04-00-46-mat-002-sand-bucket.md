# MAT-002 Sand Pile and Bucket

## Task summary
Implemented the sand pile, bucket, receiver transfer, spill behavior reuse, and carried-bucket pour input for issue #16 on `feat/sand-bucket`. The task branch is based on current `origin/main` at `eb4a0dac` (INT-003 #11 merged in PR #75).

## Relevant previous context
- MAT-005 (#62) owns bulk material amounts, capacity, acceptance, conserved transfer, fill visualization, and tilt spill. Its `BulkMaterialContainer` API was sufficient; no quantity or transfer logic was rewritten.
- INT-002/#10 and the newly merged INT-003/#11 provide generic grabbable objects and carry/drop behavior. Their interaction code was read and left unchanged.
- Existing untracked history reports, `ProjectSettings/SceneTemplateSettings.json`, `debug.log`, and `docs/MAT-001-Cement-Bag-Test-Cases.md` predated this task and were preserved.

## Changes made
- Created `SandPile` and `Bucket` prefabs with URP materials. The pile is static and has no Rigidbody. The bucket has a dynamic Rigidbody, primitive colliders, a sand-only bulk container, and generic grab support.
- Added `BucketPourAction` to hold pour intent and call MAT-005 `TransferForSeconds`; `DebugPourReceiverTrigger` now registers nearby receivers and does not pour by proximity alone.
- Added `BucketPourInput` to the bucket prefab. It requests and cancels pouring only while the bucket is held by a local player. Added the `Player/Pour` Input System action bound to hold `R`, plus its `InputActionReference` asset.
- Updated `Dev_Ghaza.unity` with sand pile, bucket containing 12 sand units, an accepting sand receiver, a rejecting receiver, receiver triggers, and a local player aimed at the bucket. Trigger volumes are 1.3 x 1.5 x 1.3 units so a carried bucket can reach the pour area.
- Recorded the `R` binding as a proposal in `docs/DECISIONS.md`; Interact remains `E` and Throw remains left mouse.
- Added five MAT-002 Play Mode tests for receiver intent, accepted/rejected transfers, nearby receiver gating, carried-bucket request/release, and tilted-bucket spill.

## Technical decisions
- The player supplies input intent; `BucketPourAction` keeps the requested receiver on the bucket and MAT-005 executes the transfer. The player never stores material quantity.
- `BucketPourInput` is attached to the bucket prefab so it can use `GrabbableObject.CurrentHolder` to gate input by the local holder, while leaving `PlayerGrab` untouched.
- Holding `R` is a proposal pending PR review and gameplay feel feedback. No manager, event bus, package, or networking code was added.
