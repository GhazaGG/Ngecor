# INT-001 Interaction Detection Review Fixes

## Task summary
Addressed review feedback from Team Lead on PR #65 (Must Fix 1-3, Should Fix 4-5) for issue #9: unified player ownership via `PlayerMovement.LocalCamera`, eliminated duplicate local player flags and fallback camera resolutions, repositioned debug HUD to lower-center with a center crosshair label, removed unused methods and dependencies, cleaned up AI plan directory, and refactored test fixtures to use realistic player hierarchy.

## Relevant previous context
PR #65 implemented first-person raycast interactable detection. Team lead review requested addressing multiple architectural items:
1. `docs/superpowers/` plan file removal per `AGENTS.md` rule 5 and project structure guidelines.
2. Ownership duality: `InteractionDetector` maintained a separate `_isLocalPlayer` state and camera fallbacks that bypassed `PlayerMovement.LocalCamera` null-safety for remote players.
3. Unused code: `SetPrompt` in `InteractableObject` and `Unity.InputSystem` dependency in `Ngecor.Interaction.asmdef`.
4. Debug HUD position: top-left (10, 10) conflicts with `SessionHUD` from NET-001; moved to lower-center screen with a crosshair "+" indicator.
5. Test fidelity: `InteractionDetectorTests` previously tested fallback path without `PlayerMovement`; updated to assemble complete player hierarchy with CharacterController, CameraPivot, Camera, and PlayerMovement.

## Changes made
- Removed `docs/superpowers/plans/2026-10-02-int-001-detect-interactable-object.md` via `git rm -r docs/superpowers`.
- Refactored `InteractionDetector.cs`:
  - Added `[RequireComponent(typeof(PlayerMovement))]`.
  - Removed redundant fields and methods: `_camera`, `_originTransform`, `_isLocalPlayer`, `_triggerInteraction`, `SetLocalPlayer`, `SetCamera`, `SetOrigin`, `ResolveOrigin`, `Start`.
  - `Awake` queries `PlayerMovement`.
  - `Detect()` strictly uses `_playerMovement.LocalCamera` every frame; returns `null` if camera is `null` (remote or uninitialized player).
  - Repositioned `OnGUI` debug box to screen center bottom (`new Rect(Screen.width / 2f - 120f, Screen.height / 2f + 20f, 240f, 50f)`) and added screen center "+" crosshair label.
  - Simplified `OnDrawGizmosSelected` to read `LocalCamera` and safely return if null.
- Streamlined `InteractableObject.cs`:
  - Removed unused `SetPrompt(string)` method; retained `SetInteractable(bool)`.
- Cleaned `Ngecor.Interaction.asmdef`:
  - Removed `"Unity.InputSystem"` assembly reference.
- Updated test suites:
  - Removed `InteractableObject_SetPrompt_UpdatesInteractionPrompt` from `InteractableObjectTests.cs`.
  - Refactored `InteractionDetectorTests.SetUp` to instantiate inactive Player GameObject, add `CharacterController`, `CameraPivot` at (0, 1.4, 0), `PlayerCamera` with `Camera`, `PlayerMovement`, `InteractionDetector`, activate GameObject, and call `SetLocalPlayer(true)`.
  - Placed interactable test targets at camera height `y = 1.4f`.
  - Added `TearDown` cleanup resetting `Cursor.lockState = CursorLockMode.None` and `Cursor.visible = true`.
  - Updated `NonLocalPlayerDoesNotDetect` to toggle `_playerMovement.SetLocalPlayer(false)`.

## Technical decisions
- Reading `PlayerMovement.LocalCamera` directly every frame ensures a single source of truth for player ownership and networking compatibility, avoiding state desynchronization between player controllers and interaction logic.
- Drawing crosshair and interaction prompt at screen center provides accurate visual alignment with camera raycast while preventing GUI overlap with session HUD elements.
