# VEH-002 PR #92 Review Fixes

## Task summary

Address the three P2 review findings on PR #92 for issue #14 and add regression coverage for the reported lifecycle, handle targeting, and disabled-movement cases.

## Relevant previous context

- The owner previously reported stable wheelbarrow pushing with and without cargo and successful traversal of the test ramp, depending on ramp scale.
- The owner clarified that the negative-scale BoxCollider warning comes from `Box_Heavy`, not the wheelbarrow.
- PR #92 was reviewed at head `5c7bde5` with requested changes covering hold cleanup, handle-only interaction, stale movement input, and automated regression tests.

## Changes made

- Restricted wheelbarrow interaction to its configured handle colliders and used handle contact points for range checks.
- Synchronized wheelbarrow and `PlayerGrab` cleanup when the player leaves range or the interaction component is disabled.
- Prevented disabled `PlayerMovement` from pushing a Rigidbody and cleared its last movement direction on disable.
- Added interaction tests for tray rejection/handle acceptance, walking away and acquiring a new wheelbarrow, and disable/re-enable; added a disabled-movement regression. Retained the existing grab/drop test as a regression check.
- Assigned the wheelbarrow prefab's left and right handle colliders through Unity Editor.
- Configured the affected test assemblies to reference NUnit explicitly while keeping their Play Mode scope. Removed duplicate Test Runner assembly references because `TestAssemblies` supplies them.

## Technical decisions

- Handle colliders are serialized on the wheelbarrow prefab so scene-independent detection can validate which part was hit.
- Out-of-range and disable paths use the same cleanup method to clear both sides of the held-interaction state.
- Play Mode remains the test mode because the existing fixtures use `InputTestFixture.Set`, which is unsupported in Edit Mode.
- No scene, package, or gameplay physics settings were changed.
