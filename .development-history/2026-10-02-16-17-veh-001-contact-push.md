# VEH-001 Contact Push Prototype

## Task summary
Implemented the generic player contact push required to make dynamic physics props, including the planned wheelbarrow, movable by the CharacterController. Added Play Mode regression coverage. Unity Editor setup and manual wheelbarrow playtesting remain outstanding.

## Relevant previous context
- PR #57 added the accepted project decision that player contact pushes apply to all dynamic physics objects.
- Team Lead review of PR #53 required desired movement direction instead of CharacterController velocity, filtering top contacts, Play Mode tests, and a simple wheelbarrow made from primitive colliders.
- The final design summary was posted to issue #13; PR #53 was closed without merging. Work continued on `feat/veh-001-wheelbarrow`, based on `origin/main`.
- VEH-002 handle interaction and NET-003 multiplayer authority remain out of scope.

## Changes made
- Added a serialized `_pushStrength` setting and `OnControllerColliderHit` handling to `PlayerMovement`.
- The handler ignores missing/kinematic bodies and downward contacts, projects desired movement onto the horizontal plane, and applies a force at the contact point. It does not set Rigidbody velocity or add wheelbarrow-specific logic.
- Added Play Mode coverage for dynamic push with bounded velocity, kinematic bodies, horizontal-only push, walking on a dynamic body, and an unchanged static wall.
- Removed `ProjectSettings/SceneTemplateSettings.json`, which Unity batch mode generated during verification and which was untracked before cleanup.

## Files affected

## Technical decisions
- Used `ForceMode.Force` with `_moveSpeed * _pushStrength`, keeping Rigidbody mass relevant and allowing Physics to integrate movement.
- Set `_pushStrength` to `2` after the Play Mode fixture showed that strength `1` did not overcome default static friction for the test body. The wheelbarrow feel and mass tuning still need Editor playtesting.
- The top-contact cutoff follows the reviewed threshold `hit.moveDirection.y < -0.3f`.
