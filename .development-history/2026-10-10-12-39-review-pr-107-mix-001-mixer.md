## Findings
- **Gate 0: dependency.** PR #98 changes the shared recipe to three ingredients:
  - `ConcreteRecipe(cement, sand, water)`, 1 cement + 2 sand + 1 water → 4 concrete, approved by the owner in its DECISIONS entry;
  - a cement sack becomes 25 cement units;
  - `CollectOnlyType` allows collecting concrete from a mixed container.
  `Mixer.cs` uses the two-ingredient API (1 + 1 → 2) and will stop compiling once #98 merges. Recommendation: keep the PR as Draft, wait for #98, then rebase.
- **Must Fix 1:** `BucketPourInput` was changed globally from hold (`IsPressed`) to one unit per press (`WasPressedThisFrame` + `RequestSingleUnitPour`). MAT-002 tests were rewritten to match. Revert; tune the rate or recipe instead.
- **Must Fix 2:** `PlayerMovement.EnablePlayerActions()` enables the action map in production code, and the player test was altered with `_actionAsset.Disable()`. DePo4l's own diagnosis report (`2026-10-08-21-08`) found the real cause, `_isLocalPlayer = false`, which the scene override now fixes. Revert both.
- **Must Fix 3: softlock.** `ShovelAction.ExecuteScoop` uses `TryGetMaterialType`, which returns false for mixed contents. Scenario: pour more sand while mixing; the result is concrete plus leftover sand, so nothing can be scooped. `Ready` returns to `Idle` only at 0 concrete, so the mixer is stuck. Fix: `CollectOnlyType` from #98.
- **Must Fix 4:** each cycle converts only one batch, and `Ready` blocks the next cycle until all concrete is removed. That undermines the mixer's purpose ("fast without player labor"). Convert all complete batches using `ConcreteMixResult.Batches`.
- **Should Fix:**
  - `Awake` overrides the Inspector collider and container mode, and the scene has two receiver triggers; `ConfigureMultipleTypesWhenEmpty` is unnecessary because the Inspector already supports `MultipleTypes`.
  - Make the mixer a prefab in `Prefabs/Construction/`.
  - The Idle status string is rebuilt every frame (GC allocation).
- **Suggestions:**
  - The rollback block in `CompleteBatch` is unnecessary, as is the unused `TryStartMixing`/`ContextMenu` path.
  - `Construction` has no asmdef, so the mixer state machine cannot be tested automatically. The TL should decide; the developer must not add one alone.
- **Process:** checklist items "AC met" and "tested locally" are ticked, but physical R/grab input was not tested (AGENTS rule 10).
