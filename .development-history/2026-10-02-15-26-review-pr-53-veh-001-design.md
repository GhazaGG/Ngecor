# Team Lead review of PR #53 (VEH-001 design) and the contact push decision

## Task summary
Team Lead session. Reviewed RyoFPS's documentation-only PR #53, which proposes the VEH-001 wheelbarrow design and implementation plan. The owner decided that walking players push dynamic Rigidbodies on contact. I recorded that decision in `docs/DECISIONS.md` (PR #57), posted a "Request changes" review and a step-by-step AI handoff prompt on PR #53, and added notes to #13 and #22.

## Relevant previous context
- `2026-10-02-02-17-review-pr-48-player-movement.md` listed "should walking players push props?" as an open design question, because `CharacterController` doesn't push Rigidbodies.
- `docs/superpowers/` was removed from PRs #48 and #52 because it falls outside `docs/PROJECT_STRUCTURE.md`.
- `docs/DECISIONS.md`: host owns physics object state, and clients send intents (AGENTS.md rule 9).

## Changes made
- **`docs/DECISIONS.md` (PR #57):** new entry "Player mendorong objek fisika lewat kontak".
  - The push is generic, comes from player movement, and is scaled by the player's intended direction and the object's mass.
  - Static, kinematic, and stood-on objects are ignored.
  - It isn't a replacement for the deliberate push/pull through handles, which stays in VEH-002.
  - Multiplayer consequence for NET-003: client pushes must go through the host.
- **PR #53 review (CHANGES_REQUESTED).** The design direction is approved: one Rigidbody, primitive compound colliders, independent cargo cubes, and no joint, script, or package until a playtest proves one is needed.
  - Required changes:
    1. Base the push on the intended `hit.moveDirection`, not `CharacterController.velocity`, which is about 0 when blocked.
    2. Ignore hits from objects the player stands on (`moveDirection.y < -0.3`).
    3. Run the tests in PlayMode, not EditMode.
    4. Don't commit per-ticket design or plan docs. Post the summary on #13 and close PR #53 without merging.
  - Additions to the design: PhysicMaterial (slippery wheel, grippy legs), manual center of mass, and Rigidbody interpolation.
- **PR #53 comment:** AI handoff prompt with ordered steps:
  - the design comment on #13 and closing #53
  - a new branch
  - exact push logic
  - PlayMode tests, including the stood-on case
  - prefab setup in the Editor
  - limited Playground changes
  - a manual playtest checklist
- **Issue #13 comment:** points to the decision and says the design summary will live on the issue.
- **Issue #22 comment:** new AC. Client players must still be able to push physics objects, without the client deciding object positions.

## Technical decisions
- **Contact push is a game-wide behavior,** so it's recorded as a product decision instead of being left inside VEH-001.
- **The push uses intended movement:** a `CharacterController` blocked by an object reports near-zero velocity.
- **Design docs live in issue comments,** not the repo. That keeps `docs/` for team documents and avoids stale per-ticket plans.

## Verification performed
- Read both design files in `origin/feat/wheelbarrow` and compared them with issues #13 and #14, `docs/GAME_DESIGN.md` (push/pull is listed as an action; "gerobak meluncur" is a sought-after chaos moment), and the DECISIONS authority and performance sections.
- Confirmed on GitHub: the review state on #53 is CHANGES_REQUESTED, the handoff comment exists, the comments on #13 and #22 exist, and PR #57 is open.
- Unity wasn't run. Two claims come from known `CharacterController` behavior and weren't observed in this project: the near-zero velocity when blocked, and the stood-on push.

## Final result
VEH-001 has an approved direction with concrete changes. The contact-push design question is closed and documented.
