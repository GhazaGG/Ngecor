# Team Lead review of PR #69 (INT-002)

## Task summary
Team Lead session. Reviewed meryzennn's PR #69 `[INT-002] Grab and carry physics object`. Posted a "Request changes" review with fix instructions and a code sketch, plus a step-by-step AI handoff prompt.

## Relevant previous context
- PR #65 (INT-001) added `InteractionDetector` and put `InteractableObject` on `Box_1`, `Box_3`, and `Ball_4`. A prefab-default bug was caught there, so this author avoided touching the prefab here.
- Issue #10 asks for separate intent and execution, one carried object, hold-point follow, no heavy jitter, and a generic system.
- `docs/DECISIONS.md` sets Interact = E through the existing action and the host-authority split.

## Changes made
- **PR #69 review (CHANGES_REQUESTED).** The approach is approved: intent and execution in separate methods, generic, single carry, physical Rigidbody kept, state restored on drop, destroyed carried objects handled.
  - Must Fix 1: carried objects are made kinematic and teleported to the hold point every `LateUpdate`, so they pass through static colliders. Releasing inside a collider can launch the object, and teleporting into dynamic props launches them. Fix: sphere-cast from the camera to the hold point and pull the hold position back before any solid collider, ignoring the player and the held object, with two new tests.
  - Must Fix 2: the PR text claims a HUD string (`[E] Pick Up Box_1`) that doesn't exist in code, and mixes tests from `main` into the count.
  - Should Fix:
    - `Box_1` now has two `IInteractable` components, and `GetComponentInParent` doesn't define which one is returned. One per object, and `Box_3` should be grabbable so the single-carry check is meaningful.
    - `PlayerGrab` is only on the Playground instance, not on `Player.prefab`.
    - `Interact` isn't wired, so a hard-coded `Keyboard.current.eKey` fallback is used. A `PlayerInteract` input action reference should be created.
    - Drop doesn't inherit the player's velocity.
  - Suggestions: pivot-based grab distance, redundant position writes, carry ignores mass. VEH-002 must not use `GrabbableObject` for the wheelbarrow handle.
- **PR #69 comment:** AI handoff prompt with 10 ordered steps and a manual playtest checklist.

## Technical decisions
- The kinematic follow is kept, because it removed the jitter. The fix limits where the hold position can go instead of switching to a joint or spring.
- The sphere-cast buffer is non-allocating, to keep carry free of per-frame allocation.
