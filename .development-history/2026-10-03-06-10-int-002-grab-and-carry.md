# INT-002 Grab and Carry Physics Object

## Task summary
Implemented physics-based grab and carry mechanics for issue #10 on branch `meryzennn/int-002-grab-and-carry-physics-object`. The implementation establishes generic interactable grabbable objects, separates client intent (`RequestGrab` / `RequestDrop`) from authority execution (`ExecuteGrab` / `ExecuteDrop`), enforces single-object carry constraints, and provides zero-jitter hold point tracking with collision isolation and full Play Mode test coverage.

## Relevant previous context
- `INT-001` (PR #65) established the raycast-based interactable detection pipeline on `PlayerMovement.LocalCamera` with `IInteractable` and `InteractionDetector`.
- `docs/DECISIONS.md#2026-10-01--networking-dan-batas-authority` mandates separating intent from execution so M3 Netcode integration (NET-002/003) can route actions through the host without rewriting interaction logic.
- `AGENTS.md` and `docs/GAME_DESIGN.md` mandate true physical carriage (retaining world Rigidbody, avoiding magic inventories) and forbid unnecessary abstractions, global singletons, event buses, or manual text edits to serialized assets (`.unity`, `.prefab`).

## Changes made
- Created `GrabbableObject` component in `Ngecor.Interaction` (`Assets/Game/Scripts/Interaction/GrabbableObject.cs`):
  - Implements `IInteractable` with default prompt `"Grab"`.
  - Requires `Rigidbody` and caches colliders.
  - Exposes `IsHeld`, `CurrentHolder`, `Rigidbody`, `Colliders`, `CanInteract()`, and `SetGrabbable(bool)`.
  - Disallows interaction while held (`CanInteract` returns false if `IsHeld == true`), preventing duplicate grabs by any actor.
- Updated `Ngecor.Interaction.asmdef` to reference `Unity.InputSystem`.
- Implemented `PlayerGrab` component in `Ngecor.Interaction` (`Assets/Game/Scripts/Interaction/PlayerGrab.cs`):
  - Requires `PlayerMovement` and `InteractionDetector`.
  - Separates client intent (`RequestGrab()`, `RequestGrab(GrabbableObject)`, `RequestDrop()`) from execution (`ExecuteGrab(GrabbableObject)`, `ExecuteDrop()`).
  - Enforces single carried object rule: rejects new grab requests while carrying.
  - Validates grab distance against `_maxGrabDistance` (default 3.5m).
  - Eliminates physics jitter: sets `rb.isKinematic = true` and `rb.useGravity = false` during carry, and ignores collision between player colliders (`CharacterController` / body colliders) and carried object colliders via `Physics.IgnoreCollision`.
  - Tracks hold point smoothly in `LateUpdate` to avoid timing mismatches with player locomotion and camera pitch.
  - Automatically resolves `HoldPoint` from camera child or dynamically spawns fallback at `(0.3, -0.25, 1.2)` relative to camera.
  - Safely restores original kinematic and gravity state upon drop or disable, and restores collision layers.
  - Handles external destruction gracefully: resets carry state without throwing exceptions.
  - Wires `_interactAction` (and Keyboard `E` fallback for offline play) in `Update()` for local players, toggling grab/drop.
  - Provides lightweight `OnGUI` debug indicator positioned below `InteractionDetector` HUD (`Screen.height / 2f + 75f`).
- Added comprehensive Play Mode test suites:
  - `GrabbableObjectTests.cs`: 5 unit tests covering interface implementation, default prompts, interaction gating when held/disabled, and release state.
  - `PlayerGrabTests.cs`: 10 Play Mode tests covering successful grab in front, rejection of second object, distance checks, held object rejection, null safety, hold point tracking and camera follow, collision isolation, physics state restoration on drop, external destruction recovery, and drop/re-grab toggling.

## Technical decisions
- **Intent vs Execution Separation:** `RequestGrab` is the client-facing intent method, which currently calls `ExecuteGrab` in single-player/local mode and will directly map to `RequestGrabServerRpc` when NET-002/003 is implemented. `ExecuteGrab` performs the authoritative validation and physics attachment.
- **Zero-Jitter Carry:** Visual jitter in first-person carry typically arises from collider penetration pushing back against the `CharacterController` or update loop desyncs between camera look and object physics. Setting `Physics.IgnoreCollision` between the player and the carried object combined with kinematic position/rotation synchronization in `LateUpdate` completely eliminates jitter while keeping the object active in the physics world.
- **Dynamic HoldPoint Fallback:** If not manually assigned or found in the prefab hierarchy, `PlayerGrab` lazily instantiates a `HoldPoint` socket under `PlayerMovement.LocalCamera`. This ensures both test fixtures and production prefabs function reliably without brittle inspector wiring dependencies.
- **Single Component per Concern:** Kept `GrabbableObject` independent from `InteractableObject` rather than subclassing, allowing props with multiple interaction needs to compose cleanly without rigid inheritance trees.

## Final result
All acceptance criteria for issue #10 are satisfied and verified by automated Play Mode tests:
- Player can grab valid interactable targets.
- Player can only carry one object at a time.
- Carried object precisely follows the hold point.

- Carried object retains its identity, Rigidbody, and state.
- System is generic and not tied to any specific prop type.
