# Implement MIX-001 concrete mixer logic

## Task summary
Implemented the MIX-001 prototype mixer logic for GitHub issue #17 and documented its runtime flow for the developer.

## Relevant previous context
- The 2026-10-06 dependency audit recorded that MIX-001 depended on MAT-002 and MIX-003 and had no implementation at that time.
- After syncing `main`, the project contains the shared bulk container and bucket pour workflow. MIX-003 is still open, so the mixer recipe remains a provisional tunable value.
- The 2026-10-02 bulk material decision requires integer quantities in world containers and says the mixer should reuse the manual cement-and-sand recipe.

## Changes made
- Added `Mixer`, with Idle, Mixing, and Ready states, Inspector-tunable batch quantities and duration, ingredient checks, output-capacity checks, and batch conversion through the shared container.
- Configured an empty mixer container to accept cement, sand, and concrete, and connected it to the existing bucket-pour receiver trigger.
- Added a small `BulkMaterialContainer.ConfigureMultipleTypesWhenEmpty` helper so the mixer can configure the existing container without changing a filled container.
- Preserved the existing `Mixer.cs.meta` GUID. No Unity scene or serialized Unity asset was edited or saved.

## Files affected
- `Assets/Game/Scripts/Construction/Mixer.cs`
- `Assets/Game/Scripts/Construction/Mixer.cs.meta` (existing GUID preserved)
- `Assets/Game/Scripts/Material/BulkMaterialContainer.cs`
- This development-history report.

## Technical decisions
- The default prototype batch is 1 cement unit + 1 sand unit -> 1 concrete unit. All quantities and mixing duration are Inspector-tunable. Align the defaults with MIX-003 when that recipe is implemented.
- Inputs stay in the mixer during the timer and are consumed only when a complete batch can be added. If ingredients are removed mid-mix, the mixer returns to Idle; if output space is temporarily unavailable at completion, it waits in Mixing until space is available.
- The existing pour trigger is reused. Mixing can be started in Play Mode from the Mixer component's `Start Mixing` context menu, keeping the current prototype interaction debug-only.
