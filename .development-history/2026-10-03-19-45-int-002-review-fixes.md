## Changes made
1. **Wall Collision & Obstruction Avoidance (`PlayerGrab.cs`):**
   - Added preallocated `_holdHits = new RaycastHit[8]` buffer and cached `_carriedRadius` (clamped between 0.05m and 0.5m based on combined collider bounds).
   - Implemented `ResolveHoldPosition(holdPoint, camera, held)` using `Physics.SphereCastNonAlloc` from camera origin towards hold point.
   - Filters out player and held object colliders, resolving the nearest non-obstructed hit distance.
   - Clamped minimum hold distance to `camera.nearClipPlane + _carriedRadius + 0.05f` to prevent the carried object from clipping into or behind the camera when the player presses directly against walls.
   - Synchronizes position strictly via `transform.SetPositionAndRotation` without dual Rigidbody/Transform writes.
2. **Drop Momentum Inheritance (`PlayerGrab.cs`):**
   - In `DetachObject()`, after restoring `isKinematic` and `useGravity`, sets `rb.linearVelocity = new Vector3(cc.velocity.x, 0f, cc.velocity.z)` from the attached `CharacterController`.
3. **Input System Integration (`PlayerGrab.cs`):**
   - Removed `Keyboard.current.eKey` fallback; `Update()` strictly processes `_interactAction.action.WasPressedThisFrame()`.
   - Ensures `_interactAction.action.Enable()` is triggered on enable and before reading input.
4. **Automated PlayMode Tests (`PlayerGrabTests.cs`):**
   - Extended `PlayerGrabTests` to inherit from `InputTestFixture`.
   - Added automated tests:
     - `CarriedObject_ObstructedByWall_DoesNotPenetrateAndReturnsWhenWallRemoved`: Verifies a wall closer than hold point prevents penetration, and object returns to hold point once wall is removed.
     - `ExecuteDrop_WhilePlayerMoving_InheritsHorizontalVelocity`: Verifies carried object inherits `CharacterController` horizontal speed upon drop.
     - `InteractInput_TriggersGrabAndDrop`: Simulates press and release cycles via `InputTestFixture` to toggle grab and drop.
     - `Update_WithoutInteractAction_DoesNotProcessInput`: Verifies no errors or actions occur when `_interactAction` is null.
5. **Assets & Unity Scene/Prefab Setup:**
   - Created `Assets/Game/Settings/PlayerInteract.inputactionreference.asset` pointing to `Player/Interact` action in `InputSystem_Actions.inputactions`.
   - Updated `Assets/Game/Prefabs/Player/Player.prefab` to attach `PlayerGrab` with `_interactAction` assigned to `PlayerInteract`; confirmed `_isLocalPlayer: 0` remains default.
   - Cleaned `Assets/Game/Scenes/Playground.unity`: removed `InteractableObject` from `Box_1` and `Box_3`, leaving them with `GrabbableObject`; kept `Ball_4` as `InteractableObject`. Removed instance component override on Player.

## Technical decisions
- **Dynamic Near-Plane Clamping:** When pressing against a wall, the distance between camera and wall can shrink to the character capsule radius (0.35m), which is smaller than a 0.5m cube. Clamping `nearest` to `camera.nearClipPlane + _carriedRadius + 0.05f` ensures the object stays physically in front of the player's chest and remains rendered without disappearing behind the near clipping plane or camera position.
- **Strict Input System Binding:** Eliminating keyboard fallbacks forces runtime and prefab configurations to adhere to the central input action map, ensuring gamepad and remapping compatibility in later milestones.
- **Single IInteractable Component per Entity:** Removing duplicate interaction components on objects ensures unambiguous raycast resolution for the `InteractionDetector` and accurate prompt text.
